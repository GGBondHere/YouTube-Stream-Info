一个在 YouTube 原生播放器中显示网速与 CDN 地区的油猴脚本，适用于桌面站普通视频和直播 `/watch` 页面。

<small>_注：测试环境为 Windows + Chrome + Tampermonkey；Edge、Firefox 尚未实测。_</small>

---

## ✨ 主要功能

- **底栏网速显示**：在播放器原生底栏显示白色连接速度与 CDN 地区，例如 `3.19 MB/s · 香港`。
- **详细统计换算**：打开“详细统计信息”后，在原始 Kbps 旁追加蓝色、加粗的换算值。
- **速度单位切换**：支持 MB/s、Mbps，底栏与统计面板同步切换，选择自动保存。
- **CDN 地区参考**：根据当前视频媒体域名识别地区，支持 IPv4／IPv6 查询优先级切换；独立音频请求不会覆盖视频地区。
- **原生界面融合**：信息随原生控制区显隐，空间不足时优先保留播放器按钮。
- **单文件安装**：无需注册查询接口账号、填写 Token、配置 VPS 或准备构建环境。

   Chrome／Edge 的运行权限说明见 [Tampermonkey 官方指南](https://www.tampermonkey.net/faq.php?locale=en&q=Q209)。

2. **安装本脚本**

   ➡️ **[点击此处安装 YouTube Stream Info 脚本](https://raw.githubusercontent.com/GGBondHere/YouTube-Stream-Info/main/youtube-stream-info.user.js)** ⬅️

## 📖 使用指南

1. **查看底栏信息**

   安装后打开或刷新 YouTube 视频页面，移动鼠标显示原生底栏，即可查看速度与地区。默认使用 MB/s，并开启地区显示，无需额外配置。

2. **查看详细统计换算**

   在视频画面上右键，选择“详细统计信息”。连接速度旁会追加蓝色换算值，原始 Kbps 保留。例如 `25553 Kbps` 对应 `3.19 MB/s`。

3. **访问脚本菜单**

   点击浏览器右上角的 Tampermonkey 图标，在 YouTube Stream Info 下操作：

   | 菜单 | 行为 |
   | --- | --- |
   | 速度单位：MB/s（切换为 Mbps） | 切换 MB/s／Mbps，底栏与统计面板同步，选择会保存 |
   | 地区查询：IPv4 优先（切换为 IPv6 优先） | 默认先查 IPv4，明确没有记录时才查 IPv6；可反转顺序，只影响地区查询 |
   | 显示 CDN 地区 | 默认开启，关闭后中止当前地区查询，继续显示速度 |
   | 重新识别 CDN | 换代理、怀疑结果过期时，重新解析当前媒体域名，并清除上次选中地址的地区缓存后识别 |
   | 清空识别缓存 | 清除 DNS、地区和地址失败缓存，保留显示偏好与服务端限流冷却 |

   没有可靠媒体域名时，重新识别不会发起查询。偏好与成功的 IP 地区缓存保存在 Tampermonkey 中；其他已打开标签页刷新后使用新设置。

速度来自 YouTube 播放器的连接速度估计，地区来自媒体域名解析后的 IP 查询。**地区是参考结果，不能保证与代理服务器实际连接的 CDN 地区一致。** 鼠标停留在地区文字上，可查看地址类型或失败原因。

## 🔍 数据含义与探测原理

<details>
<summary>展开了解：速度换算与地区显示状态</summary>

### 速度的含义

这里显示 **YouTube 播放器估算的连接速度**，不是网卡实时接收量、视频编码码率或独立测速结果。

- 使用十进制单位：MB/s 为 `Kbps ÷ 8000`，Mbps 为 `Kbps ÷ 1000`，均保留两位小数。
- `B` 表示字节，`b` 表示比特，1 字节 = 8 比特；1 MB = 1,000,000 字节。采用 1024 进制的字节单位应写作 MiB/s，本脚本不提供该单位。
- 例如 `25553 Kbps` 换算为 `3.19 MB/s` 或 `25.55 Mbps`。
- 明确的零值显示 `0.00`，无法读取时显示 `—`，后面保留所选单位。
- Network Activity 为零可能只是没有正在下载新的分片，不会被当成连接速度为零。

只采用单位明确的统计字段或文字。读取依次使用播放器统计信息、调试信息、已打开的详细统计面板；不根据任意数字或模糊字段猜测单位。

### 地区的含义

底栏显示当前媒体域名的一条解析地址对应的地区，例如“香港”。

| 显示 | 含义 |
| --- | --- |
| 香港、日本等地区名称 | 所选解析地址的地区查询结果 |
| 等待媒体 | 尚未观察到可确认属于当前视频的媒体请求，等待可识别的媒体域名 |
| 识别中 | 正在查询新的媒体域名 |
| 未知 | 域名解析或地区查询未成功；移入鼠标可查看原因说明 |

刚打开视频时通常由“等待媒体”进入“识别中”，完成后显示地区。切换视频、进出广告、播放器重建或离开播放页会使旧会话结果失效。独立音频请求不会覆盖视频地区。

</details>

<summary>展开了解：地区探测流程与准确性风险</summary>

### 探测流程

**当前视频或可关联共享媒体请求 → 媒体 Host → 公共 DoH → 一条 IP → 地区查询 → 地区名称。**

1. 观察当前播放会话的 `googlevideo.com` 媒体请求，优先使用成功的 `fetch` / XHR 响应最终 Host。依据 MIME、播放器格式与 itag 排除独立音频；SABR/UMP 共享媒体传输必须能与当前会话建立关联，不解码响应正文。Resource Timing 仅补充可靠候选，依据不足时等待媒体或显示未知。
2. 默认向 Cloudflare 查询 A 记录（IPv4）。取得有效地址后按响应顺序选取第一条，**不再查询 AAAA，也不逐个查询其他 IP 的地区**。有效响应明确没有 A 记录时，才向同一家服务查询 AAAA（IPv6）。选择“IPv6 优先”时反转顺序。
3. 网络错误、超时、服务错误、无效或矛盾的响应不等于“没有记录”：改用 Google，从所选优先级重新解析，不拼接两家服务的结果。CNAME 在同一服务中继续跟随。两种类型都明确没有记录，或两家服务均未能完成解析时，显示未知。
4. 对选中的 IP 先查询 Country。请求失败或没有有效地区时，再用 ipwho.is 查询**同一个 IP**。两家地区接口按顺序使用；失败不会促使脚本改选另一条 IP 或另一种地址类型，以免为了显示国家而掩盖查询失败。有有效缓存时直接复用。
5. 得到地区代码后转换为地区名称。悬停显示“IPv4 地址查询参考”或“IPv6 地址查询参考”。切换查询优先级会取消旧任务并清理 DNS 缓存；只有仍匹配当前会话、Host 和识别版本的结果才能更新底栏。

### 为什么只能作为参考

- **第一条解析地址不保证就是实际连接地址。** 系统和应用可以排序候选地址，也可能在 IPv6 与 IPv4 之间错开尝试并选用较早建立的连接；不是所有连接方都按 DNS 原始顺序选第一条。参见 [RFC 6724 地址选择](https://www.rfc-editor.org/rfc/rfc6724.html#section-6)、[RFC 8305 连接尝试](https://www.rfc-editor.org/rfc/rfc8305.html#section-5)。本脚本采用第一条有效地址，是减少查询、提供一个直观参考的折中。
- **公共 DoH 的结果可能与代理服务器解析结果不同。** 浏览器与代理的解析位置、解析器、出口、缓存及地址选择均可能不同；地区查询请求与视频流也可能走不同的代理路径。脚本看不到远端代理实际选中的连接 IP。
- **IPv4／IPv6 优先是查询偏好，不是实测的连接偏好。** 支持 IPv6 不代表能通过 IPv6 访问这个 YouTube 节点；访问某个 IP 检测网站的结果也不能证明视频流使用哪种地址。本脚本不探测访问者公网 IP、不测试 CDN 连通性，也不会自动推断代理服务器的地址优先级。
- **单地址结果不代表该域名的全部节点。** 同一媒体 Host 可以有多条地址，其他地址可能被标注为不同地区。本脚本只查询选中的地址，因此底栏只显示一个地区，不显示“多地区”，也不确认其他地址是否属于同一地区。
- **GeoIP 是数据库标注。** 数据可能不准确或滞后，缓存期间也不会实时重新查库；结果不证明节点物理位置、实际传输路由或视频源文件存放位置。

查询优先级不会修改代理规则、浏览器 DNS、实际视频连接、清晰度或缓冲策略。若需要严格确认代理出口实际连接的 CDN，仍需代理侧的连接数据配合。

</details>

<details>
<summary>展开了解：查询服务、缓存与隐私</summary>

| 服务 | 用途 | 发送的信息 |
| --- | --- | --- |
| `cloudflare-dns.com` | 首选 DoH，DNS JSON，先查优先地址类型，无记录才查另一类型 | 媒体 Host / CNAME 和记录类型 |
| `dns.google` | 首选解析失败时，从所选优先级重试的备用 DoH | 同上 |
| `api.country.is` | 首选地区查询 | 明确指定的目标 IP |
| `ipwho.is` | 首选地区查询失败或结果无效时备用 | 同一个目标 IP |

所有查询使用 HTTPS，不发送 Cookie，沿用浏览器的网络及代理配置。不调用查询访问者自身地区的接口，也不发送完整视频请求 URL、播放历史或账号凭据。

- DNS 缓存遵守所选地址及 CNAME 链的最小 TTL；切换到另一地址类型时，也受优先类型无记录结果的有效期约束。上限 10 分钟，最多 128 个 Host，不延长服务器 TTL。
- 成功的 IP 地区缓存保存 24 小时，最多 512 个 IP；先清理过期项再淘汰最旧项。
- 同一 Host 或 IP 的正在进行查询合并，连续媒体分片不重复启动整套流程。一次识别只选择一个 IP；全局最多两个地区查询任务并发，以限制快速切换 Host 时的请求量。每个外部请求独立超时 4 秒。
- 普通失败冷却 60 秒，HTTP 403 冷却 10 分钟；HTTP 429 遵守 `Retry-After`。缺失该响应头时，Country 冷却 60 秒、ipwho.is 冷却 24 小时。
- `ipwho.is` 当前文档列有每个出口 IP 每日 1000 次的免费限额；共享代理出口可能与其他用户共用额度。脚本只在首选服务失败时调用备用服务。

查询方可以看到本次查询 Host/IP 和请求出口 IP。这是在线识别的必要信息；脚本自身没有遥测、Cookie 读取或凭据存储逻辑。冷却时间会保存，以免刷新页面立即重复撞到限额。

</details>

## 💡 使用注意

YouTube 页面变化、扩展的注入限制、其他修改媒体请求的脚本或跨域信息隐藏，都可能影响速度读取与地区识别。依据不足时会显示缺失速度、地区“等待媒体”或“未知”，不会猜测一个地区。

卸载时在 Tampermonkey 中删除脚本，选择删除脚本数据并刷新页面即可。
